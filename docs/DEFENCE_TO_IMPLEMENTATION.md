# Defence-to-Implementation Cross-Reference

| Defence claim | Implementation evidence to produce |
|---|---|
| Browser-accessible web application | Running local dashboard and API screenshots |
| Transparent detection | Rule registry, unit tests, finding JSON and rationale |
| Risk scoring | Versioned weights, thresholds, calibration notes |
| Incident correlation | Scenario fixtures showing related findings grouped |
| Privacy-aware design | Scope record, redaction tests, retention/deletion policy |
| Bounded AI assistance | Structured prompt/output schema, rejection tests, approved actions |
| Agile delivery | Sprint log, issue links, acceptance criteria and review notes |
| Evaluation | Labelled fixtures, evaluator script, confusion matrix and usability instrument |

The presentation should only make claims that can eventually be backed by one of these artefacts.
